# 안성제철 조종사 v01 — 모델·리그 검수본

흰 외장, 흑연색 유연부, 밀폐형 금빛 바이저를 갖춘 독자 조종복 초안입니다. 제공된 정면 및 정·후면 참고 이미지를 직접 확인하고 제작했습니다. 외부 모델·유료 자산·다운로드 텍스처를 사용하지 않았습니다. 최종 아트가 아니라 체형·장갑 배치·VR 자세를 검토할 수 있는 첫 제작본입니다.

## 열어볼 파일

- `AS_Pilot_v01.blend`: Blender 5.2.2 원본. 리그, 분리된 머리/몸 스킨, 재질, 검수용 포즈, 조명과 카메라가 들어 있습니다. 기본 길이 단위는 m입니다.
- `AS_Pilot_v01.fbx`: Unity용 T 포즈 모델. 본과 스키닝 포함. 검수용 스튜디오와 조명은 제외했습니다. 애니메이션 클립은 포함하지 않았습니다.
- `AS_Pilot_Palette.png`: 16×4 색상 팔레트. UV는 재질별 단색 영역을 가리킵니다. 고유 표면 페인팅용 UV 전개나 베이크된 AO/노멀맵은 아직 없습니다. Unity 기본 재질은 이 텍스처를 샘플링하지 않고 상수 색상을 사용합니다.
- `previews/`: 정면·후면·측면·헬멧 확대 및 가드·펀치·굽힌 팔·팔 올리기 렌더.
- `Unity/PilotV01/`: Unity 자산 묶음. FBX, 재질, 프리팹, 새 검수 씬, 임포트/검증 도구와 로컬 머리 처리 컴포넌트.
- `AS_Pilot_v01.unitypackage`: 위 Unity 자산을 원래 `Assets/_Project/02_Art/PilotV01` 경로로 가져오는 패키지. Unity 6000.3.24f1 / URP 17.3.0 환경에서 검수했습니다.
- `build_pilot.py`: Blender에서 재생성하는 전체 제작 스크립트. 현재 폴더의 같은 이름 결과물을 덮어쓰므로 수정본은 따로 보관한 뒤 실행합니다.
- `model_stats.json`, `fbx_roundtrip.json`: 실제 모델 예산과 FBX 재임포트 검사 기록.

외장판은 해당 팔다리 본에 강체처럼 가중치를 부여했고, 몸통은 높이에 따라 최대 2본으로 혼합했습니다. 팔꿈치·무릎 유연부는 상하 뼈의 혼합 가중치입니다. 손가락은 3마디로 구부릴 수 있습니다. 현재 손 포즈는 파지 실루엣 검수용이며 실제 Quest 컨트롤러 메시·손 크기에 맞춘 접촉 보정은 남아 있습니다. 전완 비틀림 전용 보조 본/교정 쉐이프키는 없습니다.

렌더를 직접 확인한 후 부츠 외장의 관통 부분을 수정하고 후면 허벅지 외장과 허리 연결부를 보강했습니다. 극단적인 모든 동작에서 무관통을 보장하는 검사는 아니며, 최종 IK 적용 후 어깨·겨드랑이·손목과 프레임 간 간섭을 다시 검토해야 합니다.

## Unity 작업 위치와 열기

사용자 요청에 따라 Unity 수정 전에 **`feat/pilot-v01` 브랜치**와 독립 worktree를 만들었습니다.

프로젝트: `C:\Users\anthony\Documents\Codex\2026-09-18\anseong-steel-pilot\work\unity-pilot\AnseongSteel`

새 씬: `Assets/_Project/02_Art/PilotV01/Scenes/PilotReview_v01.unity`

기존 프로젝트의 `feat/cockpit` 체크아웃은 전환하지 않았습니다. 사용자의 기존 재질·XR 설정·Recovery 및 다른 작업의 콕핏 자산을 수정하지 않았습니다. 새 브랜치는 당시 커밋 HEAD `0d5fea7`에서 시작하므로 기존 체크아웃의 미커밋 콕핏 파일은 포함하지 않습니다. 커밋·푸시는 수행하지 않았고 원격 GitHub 브랜치 게시도 하지 않았습니다.

좌우 프리팹은 같은 FBX/스킨을 공유하고 표시색만 청록/주황으로 구분합니다. 검수 씬의 바닥과 두 원판은 위치 참고용이며 실제 콕핏 자산이 아닙니다. 프리팹은 T 포즈 원본이고 검수 씬 인스턴스에 중립 팔 자세를 적용합니다.

다른 체크아웃에 수동으로 가져오려면 먼저 그 작업의 전용 브랜치를 생성하고 `Unity/PilotV01` 폴더 전체를 `Assets/_Project/02_Art/PilotV01`에 넣습니다. 메뉴 `Anseong Steel > Pilot V01 > Build isolated review scene`는 이 경로의 재질·프리팹·검수 씬을 재생성합니다. **새 씬을 단독으로 열기 때문에 현재 씬의 수정 사항을 먼저 저장해야 합니다.** 기존 씬에 캐릭터만 쓰려면 생성된 프리팹을 배치하고 재생성 메뉴는 실행하지 않아도 됩니다.

## VR 연결 범위

- HMD + 양손 컨트롤러 3점 추적을 전제로 했습니다. 몸·발의 실제 위치를 측정하는 전신 추적이 구현되었다는 뜻이 아닙니다.
- Humanoid 본/스키닝 준비와 임포트 검수가 이번 범위입니다. HMD 높이 보정, 머리/손 타깃 IK, 팔꿈치 힌트, 몸통 추정, 발 고정, 플레이어 키 보정은 아직 연결하지 않았습니다.
- 양팔 모두 같은 수준으로 리깅했습니다. 왼쪽 사람의 왼팔/오른쪽 사람의 오른팔을 로봇 담당 팔로 선택하는 전투·네트워크 로직은 별도입니다.
- `Pilot_Head`는 머리 외장 전체를 포함한 별도 스킨입니다. `PilotLocalView.ConfigureLocalCamera(camera, reservedHeadLayer)`를 **로컬 소유권이 확정된 인스턴스에서만** 호출하면 자기 카메라에서 머리를 제외할 수 있습니다. 프로젝트에서 사용하지 않는 전용 레이어를 예약해야 합니다. 동료 머리는 기본 레이어로 유지합니다.
- `PilotLocalView`는 소유권을 추정하거나 Netcode를 자동 연결하지 않습니다. 카메라 마스크 논리를 검사하는 것과 실제 XR 카메라 스택/렌더러/멀티플레이에서 검증하는 것은 다릅니다.
- `Mount_Back`, `Mount_LeftArm`, `Mount_RightArm`은 변경 가능한 연결 위치입니다. Blender에서는 Empty이며, Unity 프리팹 생성 도구가 Chest/해당 LowerArm 아래에 같은 이름의 Transform을 추가합니다. FBX 자체에는 이 Empty를 포함하지 않습니다. 실제 프레임 치수는 아직 반영하지 않았습니다.
- 하체는 공용 발판에 서 있는 상태를 우선합니다. 기본 신장·팔 길이·발판 간격은 가정이며 실제 플레이어 체형과 하드웨어에 맞춰 조정해야 합니다.

## 검증 해석

Blender 재임포트는 52본, 몸/머리 스킨 2개와 Armature Modifier의 보존을 확인했습니다. Unity 실행 결과는 `Unity/PilotV01/Validation/unity_validation.json`을 기준으로 확인합니다. Unity 보고서/스크린샷은 에디터 결과이며 Quest 3 렌더 성능·착용감·지연·무선 네트워크 검증을 대신하지 않습니다.

`pose_validation.json`에는 Blender 여섯 자세의 유한 좌표 검사와 내보내기 전후 바인드 경계 비교가 기록되어 있습니다. 재임포트 경계 차이는 최대 약 0.000000179m였고, 재임포트된 전완 본을 회전했을 때 해당 가중치 정점 522개가 실제로 변형되는 것을 확인했습니다.

Unity에서 유효한 Humanoid, 매핑된 본 52개, 손가락 본 30개, 스킨 2개, 가중치 누락/합계 오류/비정상 좌표 0개를 확인했습니다. 로컬 머리 제외·동료 머리 유지·카메라 마스크 복원 검사를 통과했습니다. `unity_two_pilots.png`는 Unity 두 캐릭터 화면이며 `unity_local_lookdown.png`는 눈 위치를 가정한 합성 내려다보기입니다. HMD 입력을 받은 화면이 아닙니다.

검수용 URP 화면 캡처는 Unity의 [렌더 요청 API](https://docs.unity3d.com/6000.0/Documentation/Manual/urp/User-Render-Requests.html)를 사용합니다.

Quest 3 Android 단독 목표는 그대로 유지합니다. PC VR와 무선 스트리밍은 단독 성능이 부족할 경우 검토할 대안일 뿐, 현재 성능이 검증된 경로가 아닙니다.
