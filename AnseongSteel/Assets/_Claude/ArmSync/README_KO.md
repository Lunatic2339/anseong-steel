# Arm Sync 검증 씬 (Claude 작성)

VR 컨트롤러와 로봇 팔이 실제로 똑같이 움직이는지 확인하려고 처음부터 새로 만든 씬입니다.
기존 `_Project` 코드와 씬은 건드리지 않았고, 이 폴더 안의 파일만 씁니다.
로봇 모델은 `_Project/02_Art/01_Models/mecha-finger-rig-mixamo-v026.fbx`를 그대로 사용합니다.

## 만들기와 실행

1. Unity 메뉴에서 **Anseong Steel → Claude Arm Sync → Build test scene**을 누릅니다.
   그러면 `Assets/_Claude/ArmSync/ArmSyncTest.unity`가 생성됩니다.
2. Quest Link 또는 Air Link를 연결한 상태로 Play를 누릅니다.
   헤드셋이 연결되어 있지 않으면 키보드 시뮬레이션으로 실행됩니다(아래 참고).
3. Quest 단독 실행용 APK를 만들려면 **Make test scene the first build scene**을 누른 뒤 빌드합니다.
   이 메뉴는 Build Settings의 씬 순서를 바꾸므로 따로 분리해 두었습니다.

## 조작

| 버튼 (키보드) | 기능 |
|---|---|
| 왼손 Y (C) | 정면을 보고 가드 자세에서 누르면 시점과 기준점을 다시 잡습니다 |
| 왼손 X (H) | HUD 켜기/끄기 |
| 오른손 A (R) | CSV 기록 시작/정지 |
| 오른손 B (G) | 검증 마커 켜기/끄기 |
| 오른 스틱 클릭 (M) | 매핑 방식 전환: GUARD-RELATIVE ↔ ABSOLUTE |
| 오른 스틱 위/아래 (= / -) | 사용자 팔 길이 ±2cm, 배율 다시 계산 |
| 왼 스틱 클릭 (V) | 옆에서 본 로봇 화면 켜기/끄기 |

키보드 시뮬레이션: 왼손은 W/S(앞뒤), A/D(좌우), Q/E(아래위), 오른손은 I/K, J/L, U/O로 움직입니다.
Shift를 누른 채 같은 키를 누르면 손이 회전합니다. 마우스 오른쪽 버튼을 누른 채 드래그하면 고개를 돌립니다.

## 동작 방식

- 추적 공간 전체(카메라와 컨트롤러)를 `로봇 팔 길이 / 사용자 팔 길이`배로 키웁니다. 기본값은 약 3.05배입니다.
  그리고 눈 위치를 로봇의 눈 위치에 맞춥니다. 거인이 된 상태로 로봇 팔을 보게 됩니다.
- **GUARD-RELATIVE**(기본): `로봇 주먹 = 로봇 가드 + (지금 컨트롤러 − Y를 눌렀을 때 컨트롤러)`.
  10cm 움직이면 로봇 주먹은 같은 방향으로 배율 × 10cm 움직입니다.
- **ABSOLUTE**: 로봇 주먹이 거인 크기로 확대된 내 손이 있는 위치로 갑니다.
- 손목: 컨트롤러가 회전한 만큼 로봇 주먹도 그대로 회전합니다.
- 팔은 2관절 IK로 계산합니다. 팔꿈치는 아래·바깥쪽을 향하고, 팔 길이를 넘는 목표에서는 HUD에 `LIMIT`가 표시됩니다.
- 손가락은 `RobotFistPose`가 주먹 모양으로 고정합니다. 양손 모두 Blender에서 렌더링해 모양을 확인했습니다.
- 머리와 컨트롤러 자세는 `Update`와 렌더 직전(`onBeforeRender`)에 두 번 읽습니다. 그래서 화면에 보이는 로봇 팔은 그 프레임의 컨트롤러 위치를 따릅니다.

## 화면에서 보는 것

- **흰색 컨트롤러**: 실제 컨트롤러 위치입니다(확대된 공간 기준).
- **하늘색 컨트롤러**: 로봇 주먹이 있어야 할 위치와, 지금 컨트롤러의 방향입니다.
  매핑이 맞으면 로봇 주먹이 이 하늘색 복제본과 겹친 채로 함께 움직이고 함께 돕니다.
- **빨간 선**: 목표 위치와 실제 주먹 사이의 오차입니다. 팔이 닿지 않는 거리에서만 길어집니다.
- **노란 공**: 로봇 팔 길이의 95% 거리에 있는 왼쪽·가운데·오른쪽 펀치 목표입니다.

HUD 열 설명

- real: 실제 손 이동 거리(cm)
- robot: 로봇 주먹 이동 거리(m)
- gain: 배율(= scale이어야 함)
- dir: 실제 손 이동 방향과 로봇 주먹 이동 방향 사이의 각도
- pos: 목표와 주먹 사이 거리
- rot: 목표 회전과 주먹 회전의 차이
- reach: 팔을 뻗은 비율
- peak: Y를 누른 이후 가장 큰 오차(팔이 닿지 않는 구간은 제외)

## CSV

저장 위치는 `Application.persistentDataPath/ArmSync/날짜_시간.csv`입니다.

- PC: `%USERPROFILE%\AppData\LocalLow\<회사명>\<제품명>\ArmSync`
- Quest: `adb pull /sdcard/Android/data/<패키지명>/files/ArmSync`

한 프레임에 손마다 한 줄씩 기록합니다. 기록 항목은 컨트롤러 원본 자세, 실제 이동량, 목표, 로봇 주먹 위치, 각 오차입니다.

## 검사 결과 (Unity 없이 한 것)

이 환경에는 Unity가 없어서 에디터에서 직접 실행하지 못했습니다. 대신 다음 두 가지를 했습니다.

- 로봇 FBX를 Blender로 열어 손 메시와 본 웨이트를 확인했습니다. 왼손 기준으로 확인한 결과 손가락 조각은 모두 본 하나에만 붙어 있어서(웨이트가 섞이지 않음) 주먹 자세를 만들어도 메시가 늘어나지 않습니다.
- Unity 수학 함수(Vector3, Quaternion, Transform)를 같은 공식으로 흉내 낸 대체 코드에 이 스크립트들을 컴파일해서 검사를 돌렸습니다. 16개 항목이 모두 통과했습니다.
  - 주먹 결과가 Blender 렌더와 일치(양손)
  - 무작위 목표 2000개에 IK 도달
  - 팔꿈치가 항상 지정한 방향으로 굽음
  - 손 10cm 이동 → 로봇 주먹 30.5cm 같은 방향 이동
  - 반대 팔은 움직이지 않음
  - 컨트롤러 90° 롤 → 주먹 90° 롤
  - 컨트롤러 40° 피치 → 주먹 40° 피치

실제 Unity 컴파일과 헤드셋 동작은 아직 확인하지 않았습니다. 처음 열었을 때 에러가 나면 Console 내용을 그대로 알려 주세요.
