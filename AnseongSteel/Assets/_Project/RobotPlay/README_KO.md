# 로봇 플레이 첫 프로토타입

## 작업 기준

- 브랜치: `feat/player-script`
- 최초 조사 기준: `dc2d442dd2b8319b31ed356c2bc83b803f0226b9`
- 사용자 신규 리깅 모델 반영 후 기준: 원격 `develop`의 `9c75047bc61534f7d884cfc69067ce3c49cf7ed1`
- Unity 6000.3.24f1, Input System 1.20.0, URP 17.3.0, XRI 3.5.1, OpenXR 1.17.1, NGO 2.13.2. 기존 manifest를 변경하지 않음.
- 원본 체크아웃과 분리한 worktree에서만 작업. 커밋/푸시하지 않음.

## 시작

1. 이 worktree의 `AnseongSteel`을 Unity Hub에서 열기.
2. `Assets/_Project/RobotPlay/Scenes/RobotPlay.unity` 열고 Play.
3. 기본은 기기 없는 DesktopBoth 입력과 항상 열려 있는 표적. Game 뷰를 클릭하고 아래 키 사용.
4. 씬을 재생성하려면 `Anseong Steel > Robot Play > Build prototype scene`. 이 메뉴는 프로토타입 씬을 다시 쓰므로 씬을 직접 수정했다면 먼저 별도로 저장.

| 키 | 동작 |
|---|---|
| 1 / 2 | 왼쪽 / 오른쪽 잽 |
| 3 / 4 | 왼쪽 / 오른쪽 훅 |
| Q / E | 해당 팔의 마지막 연계 훅 도중 부스트 버튼 |
| Z / C 유지 | 왼팔 / 오른팔 가드 |
| WASD | 공용 기체 이동, 임시로 왼쪽 조종사 담당 |
| R | 호스트 또는 오프라인에서 전투 초기화 |

예: `1` → 약 1초 후 `2` → 약 1초 후 `3`, 훅 시작 약 0.35초 후 `Q`.
원래 위치까지 팔을 회수한 뒤 다음 동작. 한 번의 동작/접촉 유지/회수 중에는 추가 피해가 발생하지 않는다.
상단 Always open target을 끄면 보스가 좌/우/양팔 가드를 요구하는 공격을 예고한다. 예고 2초 후 판정하며 성공/실패 모두 기본 반격 시간이 생기고 방어 또는 거리 회피 성공 시 1.5초 추가된다.
현재 보스 공격은 예고 UI와 시간/거리 판정이며 공격 애니메이션은 아직 없다.

## 실제 XR 입력

`Robot Combat Authority > RobotPilotInput`에서 Source를 `XRSinglePilot`으로 변경.
Offline Side로 담당 팔 선택. 네트워크에서는 호스트=왼팔, 참여자=오른팔로 고정된다.
시작 시 담당 손을 편한 기준 위치에 놓는다. 첫 유효 추적 위치를 기준으로 자동 보정한다. 왼손 보조 버튼(기본 Y)으로 재보정한다.
담당 컨트롤러의 모든 방향 위치 변화가 해당 로봇 팔의 목표 위치로 전달되고, 양팔은 도달 거리와 보스 접촉에 제한된다. 현재 손목 회전/손가락 추적은 포함하지 않는다.
담당 손 트리거의 새 누름=부스트. 가드는 기준 위치에서 손을 올리는 동작. 반대 손 스틱=보조 이동이며 이동 권한은 임시로 왼쪽 조종사만 갖는다.
모든 XR 바인딩은 InputAction 필드에서 교체 가능하다. `motionScale` 기본 2.6. 추적이 0.25초 이상 끊기면 해당 가드/공격/연계를 해제하고 복귀 후 기준 자세에서 다시 준비해야 한다.
시점은 좌우 콕핏 자리의 1인칭이며 로봇 눈 위치가 아니다. 최소한의 콕핏 프레임만 사용한다.
Quest용 실행에서는 Source/Startup/Host Address를 빌드 전에 지정한다. Android 빌드에 이 씬을 명시적으로 포함하고 프로젝트의 기존 OpenXR 설정을 점검해야 한다. 실기기 프레임률, 입력 바인딩, 멀미와 도달 범위는 아직 확인 대상이다.

## 2인 연결

기존 설치된 NGO와 Unity Transport를 사용한 별도 LAN 테스트 씬이다. 기존 VRMP의 계정 인증/로비/음성 서비스는 시작하지 않는다.
Desktop에서는 Host (left), 두 번째 실행에서는 호스트 IP를 입력하고 Join (right). 기본 포트 UDP 7777, 같은 PC 시험 주소 127.0.0.1.
XR에서는 Input의 Startup을 Host/Client로 지정할 수 있다. 호스트가 판정, 체력, 연계, 가드, 이동을 소유하고 클라이언트에는 공통 스냅샷과 피드백 이벤트를 전달한다.
RPC 발신자와 좌우 역할을 검증하며 세 번째 접속자는 거절한다. 입력의 비정상 수치/순서 역전/과도한 범위 및 급격한 순간 이동을 거부한다. 인증이나 경쟁 게임 수준 부정행위 방지를 구현한 것은 아니다.
기존 XRINetworkPlayer 아바타/Relay 로비에 통합하려면 역할 배정과 Submit 호출을 연결하면 된다. 해당 통합은 이번 씬의 LAN 전송과 별개다.

## 판정 기본값 (최종 설계 확정 아님)

- 명중 기반 `L 잽 → R 잽 → L 훅` / 반대 순서. 동시에 들어온 잽은 완성 연계로 인정하지 않도록 최소 0.15초 간격.
- 다음 명중 제한 2.4초. 잽 8, 훅 20, 마지막 훅 부스트 x2. 보스 160, 로봇 100.
- 단독 훅 피해 기본 비활성. `standaloneHookDamage`로 변경 가능.
- 손의 전방 속도는 잽, 안쪽 횡속도는 훅으로 구분. 최소 속도 0.65, 이동량 0.12는 로봇 좌표 기준.
- 동작 유효 시간 0.7초, 원점 반경 0.22 안에서 0.12초 머무르면 다음 동작 준비.
- 바깥쪽으로 0.45 이상 준비한 동작은 훅 후보로 유지해 입력 간격에 따라 잽으로 오인되지 않게 한다. 속도는 새 입력 샘플의 수신 간격으로 계산한다.
- 가드 높이 0.4, 기본 반격 시간 3.8초. 몸이 뒤로 0.55 이상 물러나면 현재 보스 공격 범위 밖.
- 부스트는 마지막 훅이 시작된 이후 명중하기 전에 새로 눌러야 한다. 잽/단독 훅/미리 누른 버튼은 부스트하지 않는다.
- 실패, 시간 초과, 손 추적 손실 시 연계 해제. 같은 팔 잽은 첫 잽부터 다시 시작.
- 검/방패/원거리/절단/합동 필살기는 미구현. `WeaponMode`는 후속 확장을 위한 이름만 예약했다.

## 모델과 기존 코드 재사용

사용자가 올린 `mecha-red-points-mixamo-v025.fbx`의 좌우 Arm/ForeArm/Hand 뼈를 `RobotRigVisual`에 연결했다. 원본 FBX와 Blender 모델을 재작성하지 않는다. 임시 플레이어는 시야를 가리지 않도록 팔에 연결된 스킨만 표시하며 동일 모델의 두 번째 인스턴스를 표적으로 쓴다.
실제 플레이어/적 모델 확정 시 `RobotRigVisual` 참조 또는 `Replaceable Enemy Target`의 시각 모델만 교체할 수 있다. 적의 박스 Collider와 MechaVRBossTarget은 별도 판정 구성이다.
`Runtime/MechaVRBossContact.cs`와 `MechaVRBossTarget.cs`는 같은 저장소 `VR_test/Assets/Scripts`에서 변경 없이 재사용했다. 서로 다른 Unity 프로젝트이므로 이 프로젝트에도 소스를 두었다. 기존의 세그먼트 접촉 정지/중복 접촉 이벤트 억제를 재구현하지 않았다.
기존 IK 위에 얹을 수 있는 전투 상태와 입력 계층을 만들었다. 현재 씬은 길이 0.95의 두 세그먼트 검사 팔을 사용하며 업로드 모델의 뼈를 그 결과에 매핑한다. 최종 실제 크기/팔 길이/콜라이더 피팅은 추가 튜닝 대상이다.

## 상태와 피드백

`RobotPlaySession.State`는 체력, 연계/다음 담당, 가드, 공격 단계, 손 목표, 몸 위치를 제공한다. 콕핏은 이 상태만 읽는다.
`Feedback` 이벤트는 Hit, Guard, Damage, Boost, Combo, Defeated를 제공한다. `IRobotFeedback` 구현체로 표시/음향/하드웨어 어댑터를 교체할 수 있다.
현재는 콕핏 문자와 팔꿈치 부스터 표시, 모의 로그만 출력한다. 실제 힘 제어 장치나 모터로 출력하지 않는다.

## 검사 재실행

- `Anseong Steel > Robot Play > Run combat checks`: 순수 전투 상태/입력 권한 검사.
- `Anseong Steel > Robot Play > Validate build and play`: 씬 재생성 후 실제 키보드 입력을 주입하는 자동 Play Mode 검사. 완료 후 테스트용 Unity 프로세스를 종료하므로 별도 에디터에서 실행 권장.
- 결과: 프로젝트 `RobotPlayValidation/`.
- 두 프로세스 네트워크 자동 검사는 개발 플레이어에 `--robot-check-host` 또는 `--robot-check-client`, `--robot-check-report <경로>`를 전달. 해당 옵션 없이는 테스트 드라이버가 생성되지 않는다.

Quest 실기기, 서로 다른 PC 두 대, 무선 VR, 실제 햅틱, 장시간 지연/재연결 품질, Android 성능은 별도 검증이 필요하다. 자동 검사 결과와 실제 기기 검증은 구분한다.

현재 검증: Unity 컴파일, 전투 상태 검사 23개, 실제 키보드 입력/접촉/연계/부스트/가드/피격/후퇴 Play Mode 검사 9개 통과. Windows 개발 플레이어 빌드 성공. 같은 PC의 독립 호스트/클라이언트 프로세스에서 3회 명중 후 체력 104 동기화를 확인했다.
기기 없는 실행에서 OpenXR은 헤드셋 없음 오류를 기록하고 데스크톱 경로로 진행한다. 에디터 최초 검색 인덱스의 UnityEditor.Search 예외는 게임 스크립트와 별개로 기록되었다.
