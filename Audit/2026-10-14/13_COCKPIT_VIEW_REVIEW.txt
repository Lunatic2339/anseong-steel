4. 왜곡·배율과 넓어진 시야를 구분하는 측정
외부 목표의 실제 각크기 α는 눈에 대응하는 외부 카메라 위치 C와 목표 치수/거리로 정한다. 정면 중심에 놓인 폭 W, 거리 D의 예는 α=2 atan(W/(2D)). W=3m, D=6m이면 28.07°이다(설명용 가상 수치이며 현 보스 치수 아님).
눈 E에서 화면에 그려진 목표 경계 S1,S2를 보면 실제 표시 각크기 β=acos(normalize(S1-E)·normalize(S2-E)). 비교할 양은 M=β/α이며 화면 픽셀 폭만으로 M을 계산하면 안 된다. 각 외부 후보의 기준 C, world scale, 목표 W/D가 동일해야 한다.
평면 설명 예: W=3m/D=6m 목표를 4m 폭 화면의 FOV90° 영상에 표시하면 영상상 폭 1m. 화면거리 4m에서는 β=14.25°, 2m에서는 28.07°. 같은 영상을 가까이 옮기는 것은 배율 변화다. 2m에서 화면폭을 8m로 늘리되 FOV를126.87°로 함께 늘리면 목표의 표시 폭 1m/β28.07°를 유지하며 양옆 장면이 더 보인다. HMD FOV를 변경하는 실험이 아니다.
곡면은 한 배율로 설명되지 않는다. 단순 수평 타원 단면 S(θ)=(Rx sinθ,Rz cosθ), 좌측 E=(-1.05,0.075)로 계산하면 β(θ)=atan2(Rx sinθ+1.05,Rz cosθ-0.075).
같은 외부 θ=0° 영상점의 보이는 방향: V02 14.98°, A22.18°, B22.18°, C25.77° (오른좌석은 부호 반대).
같은 θ=-5..+5° 10° 구간의 눈에서의 폭: V02 9.51°, A9.53°, B8.83°, C10.41°.
따라서 C가 가까워졌다고 모든 방향/목표가 같은 비율로 확대되는 것은 아니다. 좌우 위치, 타원 비율, 목표가 차지하는 방향에 따라 변한다. 이 값은 eye-height 단면 근사/수학 계산이며 실제 FBX raycast나 보스 실측 결과가 아니다. 큰 보스의 정확한 왜곡률은 현재 사진만으로 확정할 수 없다.
머리를 옆으로 움직이면 화면상의 같은 점 방향은 바뀌지만 목표 자체의 가려짐/앞뒤 관계는 새로 렌더되지 않는다. 외부 목표까지의 운동 시차 대신 가까운 화면 표면의 시차가 지배한다. 현재 단안 중계도 실내 구조·화면 곡면·그림 속 원근·가림 단서는 남지만 목표별 올바른 양안 시차를 제공하지 않는다.
소위 화면확대 테스트의 성공은 M을 유지하면서 보이는 외부 방향 범위가 늘어나는 것이다. 적 스케일/카메라 거리/FOV/화면 범위를 한꺼번에 바꾸면 원인을 분리할 수 없다.

0 기준: 현 단안 V02/A/B/C. 기존 형상 효과와 결함 확인용이며 최종 승인안 아님. 3 feed 재사용 비용은 상대적으로 작지만 off-center/운동시차/양안 깊이 한계가 남는다.
1 우선: 고정 실내 + 개인별 양안 직접 외부 보기. 각 HMD 눈의 ray가 가상 외부 공간으로 이어지며 콕핏·자기 몸·동료는 별도 고정 실내 좌표로 표시한다. 로봇 눈은 조종사의 회전으로 돌리지 않는다. 외부 앵커 이동/방향 안정화와 실내는 분리한다. 화면을 창의 경계/장식으로 사용해도 된다. 목표별 깊이와 머리 이동 시차를 제공할 수 있고 RT 재표본화를 줄일 가능성이 있다. 두 좌석을 외부에 2.1m 그대로 벌릴지, 같은 외부 중심에서 작은 좌석별 오프셋을 줄지는 미정이며 일관된 기준을 선언하고 비교해야 한다. 서로 다른 투영을 가진 두 공간의 가림·스케일·레이어·팔/HUD 정렬과 직접 외부 optic flow 검증이 필요하다. 새 구현 필요.
2 다음: 개인별 양안 중계/가상 창. 평면은 눈 E와 화면 모서리로 off-axis frustum을 정의하고 외부 scene을 대응 시점에서 렌더해 창 너머의 각도/깊이를 맞춘다. HMD 두 대는 각자 자신의 눈용 영상만 표시할 수 있어 공용 물리 모니터의 동시 관찰자 제약과 다르다. 카메라 clipping-plane 변경만으로 해결되는 작업도 아니다.
곡면은 단일 off-axis 평면으로 전면 반구를 교정할 수 없다. 눈별 ray/왜곡 lookup 및 충분한 방향 촬영(예: 큐브맵)을 맞추거나 사실상 직접 외부 렌더로 구현해야 한다. 고정 중심 파노라마를 눈별 UV 재매핑만 하면 먼 장면의 방향은 맞출 수 있어도 가까운 로봇 팔/보스의 시차·disocclusion은 복원되지 않는다. 실제 눈별 장면 렌더 필요. 깊이 없는 영상에 양안 offset만 넣는 방식은 거리감 합격 기준으로 쓰지 않는다.
평면 중계는 기하 교정과 비교가 단순하지만 넓은 측면/상하를 위해 여러 면이 필요하다. 곡면은 넓은 방향을 감싸지만 개인별 투영/상하 coverage/경계 일치·샘플 비용이 늘어난다. 비용 우열은 GPU 측정 전 확정하지 않는다. 새 구현 필요.
전부에서 외부 카메라 관점과 실내 기준물을 같은 로봇 충격에 묶지 않는 방향을 우선 비교한다. 실내는 HMD 실제 움직임에 정상 반응하며 머리에 붙어 따라가는 HUD와 달리 공간 기준을 유지해야 한다. 외부 이동만으로도 optic flow/멀미가 생길 수 있으므로 고정 실내가 있다는 이유로 통과시키지 않는다. HMD 추적에 smoothing을 넣는 방법과 로봇 애니메이션/충격을 안정화하는 방법을 혼동하지 않는다.

7. 수치 측정 및 향후 HMD A/B 기준
현재 가능한 것: 설정/geometry 근사/기존 16-view 검토. 기존 자료에는 목표 경계 world 좌표, 실제 XR 양안 행렬, 머리 이동 sweep가 없으므로 정확한 M/입체 깊이/프레임 비용은 미측정이다.
다음 격리 구현·측정 때 기록할 최소 항목:
• 같은 모델/pose/치수와 camera-target 거리, 콕핏 Transform/scale, 외부 앵커, XR 실제 left/right eye view/projection, IPD, 좌석, 실제 머리 좌표.
• 가까운 팔/근접 상대/먼 표적 3거리, 정면/±30°/±60° 및 위아래±60°, 머리 좌우·전후±0.15m와 높이±0.10m. 범위는 초기 측정안이며 사용자의 안전한 실제 움직임/신체에 맞춘다.
• angular size M, 목표 중심 방향 오차, 가로/세로 M 비, 직선 휘어짐, 좌우 거울 조건의 일치, 양안 시차와 머리 이동에 따른 상대 위치 변화. 평면/곡면은 실제 표시 triangle 교차점을 사용한다.
• 유효 display mask 안의 coverage 누락/섹터 seam, 프레임/HUD/팔 가림, 눈별 feed 일치, GPU/CPU frame p95·p99와 dropped/reprojected frame. black pixel count 전체를 coverage로 대체하지 않는다.
• 별도로 실제 손 이동→로봇 주먹 이동, 접촉 전 주먹-목표 거리와 타격 순간을 측정한다. 시야와 팔 길이/IK 문제를 분리한 뒤 합친 조건을 검증한다.
임시 공학 목표(사용자 확정 아님): 정면·좌우30°/머리 이동 범위에서 직접 외부 기준 대비 목표 M 변화±5% 이내, 좌우 대칭 조건 크기 차이5% 이내, 방향 오차1° 이내. 주변 극단은 별도 오차표로 남기며 목표를 못 맞추면 coverage 범위를 줄이거나 투영을 바꾼다. 대상 가림/극단 원근은 오차와 분리한다. 의도된 창 테두리 외에는 유효 화면 내부 공급 누락이 없어야 한다.
HMD 렌즈 FOV는 SDK 양안 투영으로 측정하고 데스크톱 camera.fieldOfView=75를 Quest의 실제 FOV로 보고하지 않는다. 외부 RT FOV와 HMD 투영을 구분한다.

실험 순서:
① 먼저 같은 적/거리/팔 pose를 고정하고 좌우·머리 이동별 현 상태 각크기와 coverage를 기록. 상하 검은 영역을 왜곡과 별도 표시.
② 새 구현 승인이 있는 후, 형상은 하나로 고정하고 현 단안 vs 후보1 직접 외부의 정지·머리 움직임을 비교. 기존 임시 로봇시점은 깊이 참고만 사용. 실내가 사라진 결과를 최종 후보1 결과로 대체하지 않음.
③ 후보1에서 거리 단서가 개선되면 후보2의 평면 창부터 비교. 곡면 전체는 실제 필요성과 비용을 확인한 뒤 진행. 투영이 맞은 상태에서 화면의 거리/면적/고정 기준물 양을 한 변수씩 바꿈.
④ Quest 두 대/두 PC로 양쪽 역할 교대, 순서 AB/BA를 바꿔 정지→머리 이동→저속 접근/후퇴→회피→타격/부스트 순으로 짧은 블록 비교. 시야 안의 목표 찾기, 거리 순서/크기 판단, 닿을 순간 예상, 몸·동료·팔 확인, 몰입/편안함을 각각 기록.
⑤ 각 블록 전후 불편감 0..10, 중단 여부, 회복 시간, 성능을 기록. 불편감을 참으며 진행하지 않고 요청 즉시 중단. 통과 수치와 테스트 인원/체격·VR 경험 다양성은 시연 계획에서 정해야 한다. 소수 개발자 테스트를 모든 관람객의 멀미 해결로 일반화하지 않는다. 성능은 선택한 실제 refresh rate의 frame budget과 비교한다.

8. 미정 및 다음 담당에게 넘길 사항
최종 직접/중계 선택, 곡면/평면/화면 거리, 외부 조종사 간격·세계 크기 매핑, 머리 translation gain, 안정화 축/충격 강도, PCVR/Quest standalone, 주사율·성능 예산과 개인 눈높이 보정은 미정이다. 조종사는 같은 콕핏에 나란히 위치하며 옛 기획은 기립 전제다. CURRENT_HANDOFF의 이전 착석 표현은 정정되었고 착석을 새 확정 또는 동등한 확정안으로 취급하지 않는다. 본문의 좌석은 시점/배치 위치를 가리키며 의자 채택을 뜻하지 않는다.
이번 결과는 설계 검토 완료다. 게임 코드·씬·모델·공용 인계 파일 수정, 다른 채팅 메시지, 커밋·푸시·병합 없음. 새 런타임/양안 투영/Quest 편안함은 미검증. 다음 개발은 총괄 배정과 팔 추적 우선순위를 유지하며 격리 작업에서 한다.
