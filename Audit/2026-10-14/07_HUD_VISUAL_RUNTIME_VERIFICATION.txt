3. 실행 검증 설계·증거 구분
검증 도구는 saved sunwoo_HUDTest와 sunwoo_IntegratedPlay를 OpenScene만 하고 Play한다. builder/repair/save 호출 안 함. 캡처는 URP SingleCameraRequest로 실제 feed3개와 cockpit camera를 렌더한 1440x1000 PNG다. 이것은 게임 카메라 콘텐츠이며 screen-coordinate OnGUI는 포함하지 않음. desktop/Editor render이고 실제 Quest/HMD 양안/멀미/FPS 통과가 아니다.
HUD scene: 원본 no XR normal 좌우, public UseTutorialDemo hook guide(강제 API 명시), 실제 InputSystem synthetic ESC, Damage Demo/Reset/Resume/Guide toggle/Reset Settings의 ExecuteEvents pointerClick, Slider value events를 검증한다. pointerClick 직접 전달은 ray hit-test/물리 마우스/XR ray 검증과 구분한다.
Integrated scene: saved no XR 부팅→synthetic XRController neutral release/동작/Grip/Trigger→현재 RobotPilotInput→combat contact→HUD. 실제 저장 입력 source를 유지한다. 실제 자연 boss warning/impact·누적 damage·raised hands guard를 기다리고 상태 로그를 남긴다. 부스트는 실제 contact opportunity를 관찰해서 trigger edge를 공급, 성공하지 않으면 결과 그대로 기록한다. saved 모델 missing을 복구하지 않는다.
online waiting은 실제 host transport를 public StartNetwork(true)로 실행하고 peer 없는 RequestStart 거절을 검사한다. host GUI 버튼 클릭으로 실행한 것과 구분한다. host/client 실제 두기기 전체 동선은 별도 파트/실기 기준이다.
기본 startup은 EditorBuildSettings 첫 enabled 씬을 saved 상태로 Play. build는 default enabled scene 배열을 그대로 BuildPipeline에 공급하여 Windows Development 빌드·실제 exe 시작을 검증했다(8절). 통합 단일씬을 override하는 기존 검사 builder는 사용하지 않았다.
