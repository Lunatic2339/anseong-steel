2026-10-14 / 기준 develop 42e05e4

결론
현재 프로젝트에는 전투 판정·모델·콕핏·HUD·LAN의 기반이 있다. 가장 큰 공백은 이 기반들이 사용자가 정한 '같은 콕핏에서 몸으로 거대 로봇을 협동 조종하는 체험'으로 일관되게 연결되지 않았다는 점이다. 모델 파일이나 보스 공격 코드 개수만으로 게임 완성도를 평가하면 과대평가된다.
개발 순서는 기존 컨셉의 핵심 연결 복구 → 협동 판정·안내와 전투 동작 연결 → 한 판 운영·기기 검증 → 후속 협동 페이즈 확장으로 잡는다.

1. 파트별 핵심 진단

[씬·모델·아트]
확인: 통합 플레이어 팔 FBX와 구형 TrackedRobotArms의 저장된 GUID가 현재 자산과 다르다. 10/13 Unity 실행에서 Missing Prefab와 시각 팔 렌더러 부재를 확인했고 이번 정적 검사에서도 참조 불일치를 확인했다.
컨셉 차이: 사용자 후기 요구는 v026 손가락 리그/기본 주먹이다. v025로 단순 복귀하는 것을 최종 복구로 삼으면 안 된다. 붉은 홈/분리된 장갑/실제 관절축을 보존하라는 아트 방향도 유지한다.
추가 결함: 반구형 B/C의 넓은 수직 화면 범위와 현재 70도 카메라 영상/셰이더의 공급 범위가 맞지 않는다. 범위 밖 UV가 검정으로 반환되는 수식·코드 경로가 있다. 실제 보이는 면적과 편안함은 기기 검증 대상이다.
보강: 유효 본/mesh/fileID로 시각 팔을 복구하고 좌우 조종사 시점에서 확인. 이후 콕핏 후보/영상 투사/시야 가림을 함께 검증. 최신 BossV11 Blender 원본과 현 통합 호환 보스는 다른 자산이며 첫 단계에서 전면 교체하지 않는다.

[전투·보스·진행]
확인: 준비 중 오프라인 피해 허용, 절대 X좌표만으로 회피 성공, 일반 공격 방어가 오른팔 고정, 세 공격 유형이 같은 펀치 동작을 사용한다. 이전 실행 재현과 이번 코드 검토를 구분했다.
컨셉 차이: 한쪽 단독 공격으로 보스를 쓰러뜨릴 수 있고, 학습도 두 사람 각각의 참여를 보장하지 않는다. '동료와 행동을 이어 강한 마무리를 만든다'는 의도를 HP만 감소하는 전투로 축소할 위험이 있다.
보강: 공통 상태별 전투 허용 → 공격 타이밍에 실제 협동 이동하는 회피 → 좌우에 대응하는 예고/방어 → 방어 후 빈틈과 협동 반격 → 학습/승패 연결. 실험실 14패턴을 한꺼번에 켜기보다 통합 HP·권한·피해 결과의 소유권부터 정리한다.

[VR 입력·아바타·멀티플레이]
확인: 통합 입력 소유자는 RobotPilotInput인데 파일럿 팔 Follow는 비활성 ArmMotionInput 쪽에 남아 있다. LAN은 손 회전/머리/보조손 자세가 빠져 있고 위치를 바로 적용한다. 이동 스틱의 담당 손도 보조 손 기획과 다르다.
컨셉 차이: 손목만 꺾기보다 팔뚝과 주먹이 함께 움직이고, 훅에서 팔꿈치가 올라가며 뒤로 당긴 리치가 보이길 사용자가 반복 요청했다. LAN identity 회전과 아바타 입력 누락은 이 방향에 맞지 않는다.
보강: 인간 크기 좌표의 로컬 아바타 입력을 로봇 전투 좌표와 분리 연결. 이후 역할 검증을 유지하며 회전/머리/보조손 표시 동기화, 추적 손실·재교정·재접속 상태, 보간을 검증한다. 기존 입력 컴포넌트 두 개를 동시에 켜는 해결은 피한다.

[UI·빌드·성능·시연 운영]
확인: 일반 build list 시작은 SampleScene, 통합 접속은 IMGUI/키보드 중심이다. HUD는 다음 콤보 담당/남은 기회/실패 원인을 충분히 전달하지 않고 가이드도 고정 왼팔 직선이다. 기존 검증 도구는 검사 전 씬을 다시 만들거나 저장하는 경로가 있다.
컨셉 차이: 사용자는 시야를 가리지 않는 투명 HUD와 동료와의 상황 공유를 원했다. 장식이 표시되는 것과 지금 누가 무엇을 해야 하는지 이해되는 것은 다르다.
보강: 저장된 씬 그대로의 검사와 자동 복구 분리, 실제 배포 부팅/두 명 접속/준비/시작/결과/다음 참가자 초기화 동선 정리. 전투 상태에서 도출한 담당/기회/실패 안내 연결. 메뉴의 운영자와 HMD 역할은 구체화할 항목이다.
성능: 2048² 4x MSAA RT 세 개와 많은 보스 스킨/재질은 비용 구조상 측정 우선 대상이다. 현재 FPS나 Quest 단독 가능 여부는 측정하지 않았다. 팔이 사라진 씬의 낮은 비용을 최종 성능으로 삼지 않는다.

2. 과거 대화 검토로 복원한 결정
이전 질문 중 일부는 과거 대화에서 이미 답한 사항이었다. 재질문 대상에서 제거했다.
- 두 사람의 같은 방향 입력으로 전투 접근/후퇴/회피. 일반 이동도 로봇 정면 기준 방향 합의.
- 마지막 훅 적중 후 짧은 슬로우모션·버튼 안내·추가 입력으로 부스트. 게임의 팔 밀기 연출과 외골격의 저항 해제를 구분.
- 일반 해당 팔/강공격 양팔 가드. 올바른 가드 피해 0, 강공격 한팔은 완전 실패.
- 후속 검·방패는 고정 역할로 발전. 손에 쥔 검, 접고 펼치는 방패, 막기→밀치기→한 번 찌르기와 잡고 베기.
- 전체 기획의 정비 준비 시작과 마지막 합동 필살기. 지금 맨손 우선은 후속 페이즈 폐기가 아니다.
- 조종사와 로봇 시점 분리, 자기 몸과 옆 동료, 가까운 반구 화면, v026 기본 주먹·팔뚝 결합·훅 리치, 투명 HUD를 보존한다.
세부 출처와 사용자 직접 발언/assistant 제안의 구분은 00과 파트별 보고서에 있다.

3. 1차 개발 — 총괄이 담당 채팅에 착수 지시함

4. 작업 보호와 완료 판정
개발 채팅은 자기 전용 브랜치/격리 작업폴더에서 작업한다. 원본 develop의 게임 파일을 동시에 수정하지 않는다. 이미 생성한 진단 보고서는 원본 Audit에 보존된다.
자동 씬 재생성으로 기존 수작업을 덮거나 결함을 숨긴 뒤 PASS 처리하지 않는다. 모델의 GUID만 일괄치환하거나 원본 meta GUID를 바꾸지 않는다.
원격 푸시/PR 병합/원본 반영은 아직 하지 않았다. 첫 개발 결과는 변경·검증 근거가 있는 검토본으로 받고, 후속 통합 역시 개발 담당 채팅에 배정한다.
파트별 브랜치/작업폴더의 실제 생성 결과와 검사 완료는 다음 결과 수신 시 갱신한다. 이 문서의 '착수 지시'는 수정 완료 또는 테스트 통과를 의미하지 않는다.

5. 검토 한계
이번 정밀 진단은 텍스트 코드/씬 YAML/프리팹/임포트 메타/자산 목록·의존/과거 대화 중심이다. 모든 Blender 객체·FBX 내부 정점·텍스처 픽셀을 새로 열어 전수 검수하지 않았다.
10/13의 54 PASS와 PlayMode 재현은 당시 실행 증거다. 10/14 진단에서 테스트를 새로 통과했다고 주장하지 않는다. 첫 개발 채팅이 이후 수행할 실제 검사와 구분한다.
Quest 두 대·PC 두 대 실기기 동시 실행, Android 설치, 지속 프레임/발열·멀미, 실제 모터 연동은 아직 검증되지 않았다.
